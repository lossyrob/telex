# v0.3.0-rc.1: opt-in prerelease candidate

This is preparation guidance, not a publication announcement or permission to
upgrade a shared installation. The candidate includes the installer-first
Copilot App bridge fix from PR #249 and the preceding Watcher diagnostics,
backend resilience, retention and snapshot-recovery changes. A separate
operator decision is required to tag or publish it.

## Opt-in installation

After an authorized publication, `v0.3.0-rc.1` is marked **prerelease** and
**not Latest**. Default installers and `telex upgrade` continue to select the
latest stable GitHub release. Select this candidate explicitly:

```text
telex upgrade --version v0.3.0-rc.1
```

For fresh installations, set `TELEX_VERSION=v0.3.0-rc.1` and use the
tag-pinned installer; see the [installation guide](../guide/src/getting-started/install.md#opt-into-a-prerelease).
Pin the CLI plugin marketplace to `lossyrob/telex#v0.3.0-rc.1` as well.
These commands require published assets and do not install build-only Actions
artifacts. A successful preparation run creates neither a tag nor a release.

## Platforms and Watcher boundary

The candidate retains native Telex archives for Windows x64 and ARM64, Linux
x64, and both Apple Silicon and Intel macOS. Published binaries include default
features plus Entra support; compiled support is not live Entra validation.

Only the Windows x64 archive also contains `telex-watcher.exe`. The ordinary
Telex installer/updater installs Telex alone. Watcher still requires its
separate installation record, registry, backend configuration and deliberate
launch; use the [Watcher installation guide](../guide/src/guides/watcher-installation.md).
The other four archives are Telex-only. Linux Watcher source deployment also
requires its same-build process guard.

**macOS Watcher detector containment is unshipped.** macOS Telex binaries,
installer-first App bridge support and native Watcher management tests do not
establish that containment. These notes do not claim Windows real-usage
acceptance, Station completion, or closure of other campaign work.

## Copilot App: INSTALL, ATTACH, VERIFY

For a fresh App session exposing `install_extension`, install the bridge
**before** `copilot attach --copilot-bridge` or `copilot resume`. The candidate's
`telex copilot skill` prints tool arguments using a pinned, full Git build id:

```json
{
  "url": "https://github.com/lossyrob/telex/tree/<version.build_id>/copilot/bridge",
  "scope": "session",
  "name": "telex-bridge"
}
```

Use the full source commit from the selected binary's `telex --json version`,
and verify that published source matches the embedded bridge. Missing, short
or unknown build ids cannot supply a valid installer URL; a build id is a
diagnostic claim, not provenance by itself. Never substitute floating `main`.

The installer downloads files **and reloads** extensions; it is not reload-only.
After installation, attach with the intended backend/options, verify
`station_health: attended_push` and `push_registered: true`, then confirm actual
delivery and disposition.

An existing `telex-bridge` name is refused, including files already written by
attach. Preserve a live bridge and its bindings; otherwise use supported reload
or startup discovery. Do not invent a second bridge name targeting the same
session socket. Deliberate replacement requires detaching every affected
binding, reinstalling after the last detach removes the files, then reattaching
with the original backend/options, including `--wake-on-cc` where used.
The [delivery guide](../guide/src/guides/copilot-push.md#app-session-installer)
also retains the supported pull fallback.

One source-matched macOS Copilot App 1.1.35 isolated SQLite experiment verified
installer-first loading, a pushed challenge and dispositions. It does not prove
every App build, OS, backend, or upgrade path supports this procedure.

## Version, schema and rollback cautions

Telex's package, lockfile entry, plugin and marketplace identify as
`0.3.0-rc.1`. The independent `telex-console` and `telex-watcher` packages remain
`0.1.0`. Runtime/build identity, backend schema, Watcher registry metadata,
detector schema, IPC and bridge protocol are separate axes; release numbering
does not bump them.

Back up before migration. Telex still supports backend schemas 2 through 3 and
protocol 1.5. Genuine released v0.1.2 supports schema 2/protocol 1.4; after
schema-3 migration, its store guard and the candidate rollback guard refuse the
incompatible downgrade. A retained previous executable is not a rollback plan.
Use ordered authenticated daemon replacement and reattach wanted addresses.

Watcher registry metadata migrates from 2 to 3 independently of Telex's schema
and detector schema v2. Earlier Watcher binaries refuse metadata 3, including
marked backups and restored fenced registries. A binary swap cannot undo that
migration. Preserve compatible owner-only snapshots, executable identities,
installation records and logs; inspect post-backup sends and receiver dedupe
history before resuming restored watches. Never bypass version guards, copy a
live SQLite main file without journal state, or reset the registry to appear
healthy.

## Candidate evidence

Bind preparation evidence to the actual commit and tree, not a moving branch.
All five native Release jobs must prove source/build identity, genuine v0.1.2
explicit-version upgrade, populated schema-2 migration, schema-3 reopening,
fresh installation, negative controls and owned cleanup. Both Windows jobs
retain native capability-publication error classification. Windows x64 also
requires archive installation and forward Watcher upgrade from source baseline
`7036e7103aae4416cf0a0e2030175dc901ece893`, with its existing registry and
backup/restore checks. The separate Linux PostgreSQL 16 leg remains required.

Build-only archive names contain the sanitized dispatch ref. Proof reports
record the identical bytes served under a `v0.3.0-rc.1` asset alias, source SHA,
hashes and commands. Retain every failed attempt and limitation. Prior release
or different-head evidence does not prove this candidate; any later source
change needs fresh exact-source evidence before publication.

These are required evidence surfaces, not assertions that they have passed.
They do not establish universal App support, macOS Watcher containment,
every-platform PostgreSQL, live Entra, mixed-image live IPC, every installer
default-root branch, signing, or real shared Windows usage acceptance.
