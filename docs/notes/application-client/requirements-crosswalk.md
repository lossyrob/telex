## Historical issue #12 proposal dispositions

The exact pre-convergence issue #12 body is preserved at
[application-client-issue-12-original.md](../../design/history/application-client-issue-12-original.md).
It is historical evidence, not contract authority.

| Historical proposal element | Disposition | Rationale | Remaining owner and blocking effect |
|---|---|---|---|
| Runtime-agnostic application integration over one Telex fabric | accepted | The contract preserves one semantic boundary across hosts and bindings. | Supported client core; no consumer implementation proceeds without conformance. |
| Stable semantic operations for lifecycle, send, receive, reply, acknowledgment, disposition, status, and discovery | accepted | AC-C01 through AC-C20 define the semantics without selecting a language API. | Supported client core and first binding. |
| Holder/waiter as the general Application Client model | replaced | Holder/waiter is one CLI runtime projection, not a shared semantic contract. | CLI remains a consumer; other hosts choose binding shapes without changing semantics. |
| Client-owned heartbeat, cursor, and generic auto-registration | replaced | Current daemon membership, typed `NeedsAttach`, explicit recovery policy, exact-recipient acknowledgment, and fenced resync govern. | Supported core must use daemon authority and preserve strict membership. |
| Push, pull, callback, async iterable, or poll as normative delivery semantics | deferred | These are binding shapes. AC-C09 defines the invariant receive envelope underneath them. | First-binding design; does not block semantic checkpoint. |
| TypeScript/napi-rs first, package names, C ABI, PyO3, JNI, or language sequence | deferred | Language and packaging are implementation-node choices. | First-binding and later binding nodes; no product may treat the historical sketch as approved API. |
| Stabilizing a public raw socket/JSON-lines protocol | deferred | A public protocol requires a separate compatibility and security decision. Raw private daemon IPC is not a fallback. | Supported core/protocol design; consumers remain blocked from private IPC. |
| TypeScript `Station` interface and method signatures as contract authority | rejected | The sketch is informative evidence only; API shape follows after semantic acceptance. | First binding must prove conformance to this contract. |
| Runtime-specific interrupt cancellation policy | deferred | Attention delivery policy belongs to a host/runtime binding, not the shared client semantic core. | Binding and consumer integration nodes. |
| CLI parsing, subprocess courier, spike environment variables, store-path fingerprints, or private helpers as production client seams | rejected | They bypass typed identity, receipt, recovery, and backend parity. | Affected consumer remains blocked until the supported client exists. |

## Boundary result

The convergence accepts every shared semantic requirement while rejecting the
idea that Watcher or Operator Station may compensate for a missing shared
semantic with a product-private client. Watcher remains send-only and owns
detector policy. Operator Station remains bidirectional and composes ordinary
receive, metadata-bearing reply, disposition, history, and source-resolution
primitives; presentation and human workflow policy remain outside the shared
client. Both depend on one capability-aware Application Client contract.
